# file_editor

`file_editor` 是受限文本文件的写入与编辑工具。它通过一个本地工具入口完成新建或整体覆盖文件、精确替换文字和结构化补丁修改。

## 路径行为

- 相对路径从 e-b 宿主运行位置开始解析。
- 绝对路径可以指向当前项目外的文件或目录。
- 实际能写入哪里，仍然受运行进程的操作系统权限限制。
- 本工具只负责修改，不提供读取、列目录、路径搜索和文本搜索能力。

## 安全边界

- 只处理文本文件；写入内容中的空字节会被拒绝，补丁的删除与移动也要求目标是文本内容。
- 超过大小限制（`maxFileBytes`）的文件或写入内容会被拒绝。
- `write` 和 `edit` 支持 `expectedHash`：传入时目标必须存在且内容一致，否则失败并回报当前真实 hash。
- 精确编辑默认要求旧内容只出现一次，除非明确使用 `replaceAll`。
- 结构化补丁会先规划完整变更，再真正写入；如果规划失败，不会留下前半段修改；写入采用同目录临时文件后改名就位，不留半截文件。
- 原有文件的换行风格（LF / CRLF）会被保留；编辑与补丁会把输入换行适配成文件自身的风格，新建文件默认使用 LF。

## 结果信息条

每次成功修改都会在返回正文末尾附一条 `[file_editor]` 信息条，给出本次操作的关键事实（新 hash、替换数、变更路径数等），新 hash 可直接用于后续操作的 `expectedHash`。

## 操作类型

- `write`：创建或整体覆盖文本文件。
- `edit`：执行精确文本替换；默认要求旧内容唯一，`replaceAll` 为 true 时可替换全部匹配；空 `oldString` 只允许创建缺失文件。
- `apply_patch`：应用结构化的多文件补丁，支持新增、删除、更新与移动，先规划后写入。
  - 每个 `@@` 段独立定位、按顺序应用，段与段之间可以有间隔。
  - 补丁正文中的空行按空上下文行对待；文件段末尾的空白属于格式，不算内容。
  - 同一文件在一份补丁里只能出现一次。
  - 语法不合规（结束标记后还有内容、`@@` 后带内容、新增/删除段带移动指令、非法行前缀等）会明确失败。

## 配置项

- `maxFileBytes`：允许写入、编辑和补丁处理的文本内容最大字节数。
