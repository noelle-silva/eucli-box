# image_reader

从文件系统按路径读取一张图片文件，判定格式与大小并按需压缩，然后加载进当前会话供模型查看。

## 定位

image_reader 是工具体系中的独立基础读取动作：一次调用把磁盘上的一张图片引入会话。它存在的目的是让模型能够查看文件系统里的图片——比如工作区中的截图、素材图。

它与相邻工具严格分工：

- 与 `file_reader`：`file_reader` 只读文本、拒绝二进制；本工具只读受支持图片。
- 与 `session_image`：`session_image` 引用会话中已存在的图片；本工具从文件系统引入一张新图片。
- 与 `ai-image`：`ai-image` 生成图片；本工具只读入既有图片文件。

## 动作

唯一动作：传入 `path`（必填），读取该图片文件并加载进当前会话。

- 路径基准：工作区会话以工作区首个注册目录为基准，其他会话从 e-b 宿主运行位置解析；绝对路径允许使用。路径越界由宿主围栏把关。
- 支持格式：仅 PNG / JPEG / WebP / GIF，按文件魔数识别，不认扩展名。
- 体积处理：源文件超过 `maxSourceBytes` 直接拒绝、不读入；超过 `maxImageBytes` 时自动压缩（等比缩放、透明合成白底、JPEG 重编码）；压缩后仍超过 `maxImageBytes` 则原地拒绝并提示文件太大。
- 只读源文件：不修改、不新建、不删除磁盘上的任何文件。

## 两层压缩的关系

本工具的压缩只作用于「加载进会话的这张图」。图片写回会话后，在宿主视角就是该会话图片的原图；宿主既有的会话图片多版本机制会再基于它生成小副本，超预算历史图发小副本。两层机制正交叠加，工具不接管、不修改宿主的预算与小副本机制。

## 能力

声明两项标准能力：

- `workspace:read`（工作区路径，注入类，无需授权）：宿主注入工作区路径并对路径参数做围栏校验。
- `session-attachments:write`（写入会话图片，索取类，需用户在工具设置页开启授权）：把图片经宿主代写落盘并挂回本次回复。

## 配置项

- `maxImageBytes`：入库上限（触发压缩与压缩后拒绝的同一阈值），默认 4 MiB。
- `maxSourceBytes`：源文件读取硬上限，默认 64 MiB。
- `maxDimension`：压缩长边像素上限，默认 1568。
- `jpegQuality`：压缩 JPEG 质量，默认 80。

## 边界

- 不做图片编辑、生成、批量格式转换、多图批量读取；一次调用一张图。
- 不做目录遍历、文本读取、路径搜索。
- 不接管宿主会话图片的预算与小副本机制。
- 物理路径只在工具进程内使用，交回宿主的只有逻辑标识与图片数据。
