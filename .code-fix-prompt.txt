══════════════════════════════════════
第四步：修复原则
══════════════════════════════════════

必须遵守：
- 不论改动大小，代码的标准化、模块化都是强制要求。
- 代码体系的模块化、标准性、优雅性优于最小改动。
- 拒绝补丁式代码、补丁式修改，要做就做优雅统一的机制。
- 要做就一次性做到可用，不留下债务。
- 做机制必须做到能用，拒绝用无意义兜底掩盖真实问题。
- 优先复用系统内已存在的同源能力，并抽象为统一机制。
- 遵守根系涌现：复杂行为必须由职责单一、边界清晰的基础动作自然协作产生。
- 遵守奥卡姆剃刀：如无必要，勿增实体；不得为了抽象词新建 Manager / Engine / Controller / Service 等中心化实体。

客户端边界必须保持：
- 客户端只做用户交互、数据展示、请求转发。
- 客户端不维护角色、供应商、会话等业务权威数据。
- 客户端不做业务判断。
- eucli-box 是数据真源。
- HTTP 用于命令发送，WebSocket 用于实时事件接收。

错误处理必须快速失败：
- 不得静默吞错。
- 不得在 eucli-box 不可用时让客户端自行接管业务逻辑。
- 不得用本地缓存伪装为权威数据源。
