# eucli-box

eucli-box 是本地 AI 工作台的业务端，使用 Go 编写，负责角色、会话、模型供应商、工具调用、表情包和辅助生成能力的全部业务逻辑、数据保存与服务暴露。

## 架构关系

eucli-box 是整个系统的业务核心（以下简称"业务端"或"e-b"）。所有业务数据、业务逻辑、提示流组装和模型调用都在业务端完成。

客户端（eucli-studio）是业务端的纯操作面板和展示面板。客户端本身是一个前后端分离的应用：前端为 Web UI，后端为 Tauri sidecar 启动的 Go 进程。客户端后端只做协议转发和本地投影缓存，不承载任何业务逻辑。

```
┌─────────────────────────────────┐
│         客户端 (eucli-studio)      │
│  ┌───────────┐  ┌─────────────┐ │
│  │  Web UI   │──│ Go sidecar  │ │
│  │ (操作/展示) │  │ (协议转发)   │ │
│  └───────────┘  └──────┬──────┘ │
└─────────────────────────┼───────┘
                          │ HTTP/WS
┌─────────────────────────┼───────┐
│      业务端 (eucli-box)          │
│  全部业务逻辑 / 数据存储 / 模型调用  │
└─────────────────────────────────┘
```

客户端不做任何业务判断，只负责：
- 展示业务端返回的数据
- 把用户操作翻译成对业务端接口的调用
- 本地缓存投影（加速展示，不参与业务）

## 数据目录约定

- `data/` 是运行期数据目录，不是源码目录。
- `data/meta/` 只用于保存长期辅助信息，例如版本标记、功能偏好和模型分组等稳定配置。
- 角色会话统一保存到 `data/sessions/roles/{roleId}/{sessionId}/`，对应的角色索引放在 `data/sessions/roles/index.json`。
- 群组会话和工作区会话分别保留在 `data/sessions/groups/` 与 `data/sessions/workspaces/` 下。
- 模型请求过程不再默认落成独立流水文件，避免运行期目录持续积累无下游消费的小文件。
- 历史遗留的请求流水文件不会再新增，可在确认不需要追查旧请求后单独清理。

## 维护原则

- 长期设置和短期运行痕迹分开处理。
- 没有真实下游消费的数据不默认持久化。
- 如未来需要请求诊断能力，应重新设计为可开启、短期保存、可自动清理的独立诊断机制。

## 异步工具结果身份

- 异步工具结果回到会话时，内部保存为独立的“异步工具返回”身份，不再伪装成用户发言。
- 客户端根据这个身份展示为后台工具返回，避免用户气泡和系统回灌内容混在一起。
- 后台结果完成后，如果当前会话没有正在处理的流程，会自动接上下一轮处理，把结果带进后续上下文。
- 如果后台结果在 AI 正在输出时完成，会等当前输出自然结束后立刻接入，不需要用户再发一条消息触发。
- 自动接上的下一轮会沿用异步任务发起时的运行外壳，避免与同步工具返回后的继续表现分叉。
- 后台结果只作为过程材料进入消息链，不会覆盖已有回复；后续回复会接在后台结果之后，刷新会话时也不会因为后台结果排在末尾而把真正回复挤出可见路径。
- 运行通知把后台结果显示到当前会话后，会同步写回长期会话记录，避免客户端重启后从旧记录恢复时把后台返回误显示成用户消息。
- 客户端重启读取长期记录时，会保留后台工具返回身份，避免中间整理过程把它误归到用户消息一侧。
- 交给模型前仍按已有工具结果含义处理，不建立另一套模型交互路线。
- 本机制沿用原有聊天消息流和运行事件流，不建立独立的回灌展示路线。

## 回复生成约定

- 重新回复基于目标回复之前的完整聊天上下文重新生成，不要求目标回复前一段必须是用户发言。
- 重新回复生成的新内容继续沿用现有路线分支行为，不覆盖被重新生成的旧回复。
- 从用户消息继续回复仍保持原语义，只基于该用户消息所在的上下文继续生成。

## 群聊接入

- 群组会话现在支持真实发送、继续回复、重新生成和停止，发言时按群组成员各自的角色设置执行。
- 群组底部输入栏不提供当前会话临时模型和思考程度设置，避免把角色聊天的专属控制混入群组场景。
- 群聊的运行状态刷新、点选会话、改名和删除都按群聊目标独立处理，不会串到其他会话。
- 群聊与单聊复用同一套会话保存与刷新基础能力，避免出现两套分叉流程。

## 工作区入口

- 工作区现在作为和角色、群组并列的第三入口存在。
- 进入工作区后，先选择工作区，再选择当前角色；会话归属由“工作区 + 当前角色”共同决定，发言者属于当前角色。
- 工作区会话支持创建、切换、发送、继续回复、重新生成、改标题、删除和运行状态回流。
- 同一个工作区内，不同角色拥有各自独立的会话列表、当前会话、输入草稿和运行状态提示。
- 工作区管理支持新建、编辑、删除，内容包括工作区名称、目录清单和工作区提示词。
- 工作区设置中会展示后台生成的实际提示词，用户可以看到工作区资料最终会如何进入对话上下文。
- 工作区目录没有“默认目录”概念，所有登记目录平等参与上下文构建。
- 工作区删除只删除工作区定义，不删除历史会话数据。
- 工作区里的文件读写和命令工作目录会先经过工作区目录范围确认，再进入角色工具权限确认。

### 使用方式

1. 在客户端顶部入口中选择“工作区”。
2. 进入某个工作区后，选择当前角色，再开始聊天。
3. 如需维护工作区，到“设置 → 工作区管理”中编辑名称、目录和提示词，并查看实际提示词展示区。
4. 工作区目录或提示词修改后，下一轮对话即时生效。

### 行为边界

- 工作区当前只支持单角色对话，不支持工作区配合群聊。
- 工作区不会绑定某个固定角色，任何角色都可进入任何工作区。
- 工作区删除只删除工作区定义，不删除按角色分层保存的历史会话数据。
- 工作区路径范围不是安全沙箱，只用于减少误操作；越界时会进入用户确认，而不是直接拒绝。
- 命令文本里的路径不会被完全解析，围栏只检查命令工作目录参数。

## 当前重点能力

### 占位符子系统

占位符子系统是业务端中的独立子系统，用于把常用提示材料登记成一个名字，然后在角色提示词、工作区提示词、群组提示词或 hook 提示词中使用 `{{名字}}` 引用。

发送给 AI 前，其他业务通路只向占位符子系统请求替换结果；替换发生在内存里，不会改写角色、工作区、群组、hook 或会话中的原始保存内容。

### 使用方式

1. 打开客户端“设置 → 占位符管理”。
2. 新建占位符，填写名字、值和备注。
3. 在提示词中写入 `{{名字}}`。
4. 可在管理页使用解析预览查看替换结果。
5. 可用收藏夹整理占位符，收藏夹只影响展示和筛选，不影响实际替换。

### 行为边界

- 占位符名字全局唯一，保存时不允许重复。
- `{{ 名字 }}` 和 `{{名字}}` 等价，名字前后空格会被清理。
- 未注册的名字会原样保留，不会报错。
- 占位符的值可以继续引用其他占位符，会递归展开。
- 循环引用会保留原始写法，并在问题看板里标记为循环引用。
- 本期不支持动态值、批量操作和转义语法。

### 设置页左侧分区栏

客户端设置页面的分区入口现在固定在页面左侧，右侧显示当前分区内容并独立滚动。

这个调整只改变设置页面内部的分类选择位置和滚动边界，不改变各设置分区自己的内容和保存行为。

### AI 工具提示说明编辑

可以在客户端的“设置 → AI 工具 → 查看/配置”中，为单个工具填写用户版本的提示说明。

填写后，这个工具在所有角色中都会使用用户版本说明来介绍自己；清空或点击“恢复默认”后，会回到工具包自带的默认说明。

### 使用方式

1. 打开客户端设置里的“AI 工具”。
2. 选择一个工具并进入“查看/配置”。
3. 在“工具提示说明”中填写自定义说明。
4. 保存工具配置后生效。
5. 如需回到工具包默认说明，点击“恢复默认”并保存。

### 行为边界

- 这个能力跟着工具走，不跟着角色走；同一个工具的自定义说明会影响所有使用它的角色。
- 自定义说明是完全覆盖，不是追加补充；填写后 AI 只看到用户版本说明。
- 恢复默认不会删除工具本身，只会清除用户版本说明。

### 异步工具调用

工具现在支持同步和异步两种调用方式。同步调用保持原样；异步调用会先记录为后台任务，当前流程收到“已受理”后继续推进，真实结果稍后回到当前会话，并在完成后主动带动下一轮处理。

### 使用方式

1. 工具必须声明默认调用方式，未声明会被视为工具配置不完整。
2. 单次工具请求可以指定 `invocationMode` 为 `sync` 或 `async`。
3. 异步任务受理后，会在助手消息里显示为后台处理中。
4. 输入栏旁边的“异步”入口可查看当前会话的后台任务列表，入口数字只统计正在运行的任务。

### 行为边界

- 第一版异步任务入口只读展示，不提供取消和重试。
- 异步任务受理后不会让当前流程原地等待真实结果；如果结果尚未完成，流程会继续向后推进。
- 异步任务记录跟随会话保存，重启后未完成的运行中任务会标记为失败，已出结果但未回灌的任务会保留待回灌。
- 异步结果不会插入同步工具链中间；后台完成后会先作为后台工具返回写入会话，再进入后续处理。
- 当前回复正在进行时返回的异步结果，会在当前回复收尾前再次检查并接入，避免滞留到下一次用户发言。
- 异步结果进入会话后，下一段回复会沿着它继续生成；界面刷新会按消息接续关系恢复当前路径，避免把后台返回误当作用户消息或最终回复。
- 异步结果触发的后续处理沿用任务发起时的显示方式、临时模型、思考程度和提示词选择。
- 如果工具正在等待用户确认时有异步结果到达，等待会被系统事件打断，并与用户主动拒绝区分。

### 手动上下文压缩

当一个会话变长后，可以在当前聊天中输入 `/compact` 主动整理上下文。

压缩完成后，系统会在会话中追加压缩边界和上下文摘要。旧聊天不会被删除，后续继续对话时会使用“最新摘要 + 最近原文”的方式延续上下文。

### 使用方式

1. 在设置里的“AI 微服务”中配置“上下文压缩”。
2. 选择用于压缩的供应商和登记模型。
3. 设置压缩后保留最近多少条原文消息，默认是 15 条。
4. 回到聊天，在当前会话输入 `/compact`。

### 行为边界

- `/compact` 只做手动触发，不会自动压缩。
- `/compact` 不接受参数，也不能携带附件。
- 未知斜杠命令不会被当成普通聊天发送。
- 压缩不会删除旧消息，只会追加系统记录。
- 压缩产生的系统记录和已被摘要覆盖的历史消息会受到保护，不能被普通编辑或删除。
- 第一版不做自动区间控制、旧工具结果变轻、切换模型自动压缩和插件化策略。
