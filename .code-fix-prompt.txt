调用方只会告诉你一个信息：当前要修复第几轮联审报告。

你必须读取该轮次目录下的全部审查报告：`.task\交叉联审报告\第N轮\*.md`。
例如：修复第 2 轮问题时，必须读取 `.task\交叉联审报告\第2轮\` 下所有 Markdown 报告。

修复完成后必须写入修复报告：`.task\修复报告\第N轮\修复报告.md`。
例如：修复第 2 轮问题时，修复报告必须写入 `.task\修复报告\第2轮\修复报告.md`。

你必须自行创建对应轮次目录。不要在会话里展开说明修复细节；会话里只允许简短说明修复报告已写入哪个文件。

推荐使用 PowerShell 写入修复报告，避免工具侧普通文件写入权限不一致导致报告缺失。写入方式如下：

```powershell
$dir = '.task\修复报告\第N轮'
New-Item -ItemType Directory -Force -Path $dir | Out-Null
$path = Join-Path $dir '修复报告.md'
$lines = @(
  '# eucli-box 客户端代码修复报告 · 第N轮',
  '',
  '## 一、修复结论',
  '',
  '- 修复轮次：第N轮',
  '- 修复状态：完成 / 阻塞',
  '- 验证状态：通过 / 未通过 / 未运行'
)
Set-Content -Path $path -Value $lines -Encoding UTF8
```

实际写入时必须把 `N` 替换为当前修复轮次，并把完整修复报告内容写入 `$lines`。

第四步：修复原则
══════════════════════════════════════

必须遵守：
- 不论改动大小，代码的标准化、模块化都是强制要求。
- 代码体系的模块化、标准性、优雅性优于最小改动。
- 拒绝补丁式代码、补丁式修改，要做就做优雅统一的机制。
- 要做就一次性做到可用，不留下债务。
- 做机制必须做到能用，拒绝用无意义兜底掩盖真实问题。
- 优先复用系统内已存在的同源能力，并抽象为统一机制。
- 遵守根系涌现：复杂行为必须由职责单一、边界清晰的基础动作自然协作产生。
- 遵守奥卡姆剃刀：如无必要，勿增实体；不得为了抽象词新建 Manager / Engine / Controller / Service 等中心化实体。

客户端边界必须保持：
- 客户端只做用户交互、数据展示、请求转发。
- 客户端不维护角色、供应商、会话等业务权威数据。
- 客户端不做业务判断。
- eucli-box 是数据真源。
- HTTP 用于命令发送，WebSocket 用于实时事件接收。

错误处理必须快速失败：
- 不得静默吞错。
- 不得在 eucli-box 不可用时让客户端自行接管业务逻辑。
- 不得用本地缓存伪装为权威数据源。
