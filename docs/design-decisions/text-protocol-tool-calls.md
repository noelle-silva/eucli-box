# 文本协议工具调用属于会话正文

## 设计决定

`<<<TOOL_REQUEST>>>` 文本协议工具调用是助手消息正文的一部分。保存助手回复时，必须把这段文本原样保留在 `message.content` 和文本消息片段里。

文本协议调用本身不能持久化为“工具调用 part”。它的调用记录就是正文里的那段 `TOOL_REQUEST` 文本。

运行时可以临时解析 `TOOL_REQUEST` 来执行工具，但解析产物只是一次运行过程里的临时执行意图，不是需要落库的调用记录。

工具执行完成后，可以把工具结果保存为 part。这个 part 表达的是“结果”，不是“调用”。结果 part 可以包含和正文中某个 `TOOL_REQUEST` 对应的必要关联信息，但不能反过来复制、替代或伪装成文本协议调用本身。

## 为什么这样设计

文本协议工具调用和模型供应商的原生工具调用不是同一种契约：

- 原生工具调用是供应商接口返回的结构化事件。它本来就不是助手可见正文，所以它的调用记录需要以结构化 part 保存。
- 文本协议工具调用是模型亲自写出的文本。模型把协议块作为消息内容输出了，所以它的调用记录必须以普通助手正文保存。

如果把文本协议调用再保存成类似原生工具调用的 invocation part，同一个调用就会同时拥有两个身份：正文里的文本调用，以及结构化 part 里的工具调用。这会混淆语义，也会诱导后续维护者把文本协议错误地当作原生工具调用处理。

如果从 `message.content` 里移除协议块，前端就无法定位文本协议调用。前端应该从助手正文里读取和渲染 `TOOL_REQUEST` 调用本身，再从结果 part 读取和渲染工具执行结果。

## 根职责

- `message.content`：保存完整会话正文，包括 `TOOL_REQUEST` 文本协议调用。
- 文本协议解析器：从当前模型回复里识别 `TOOL_REQUEST`，生成临时 `ToolIntent` 供本轮运行执行。
- 工具执行器：根据临时 `ToolIntent` 执行工具。
- 结果 part：保存工具执行结果，以及和正文里对应 `TOOL_REQUEST` 的必要关联信息。
- 前端渲染：从正文渲染文本协议调用，从结果 part 渲染执行结果。

## 运行时契约

工具调用系统只负责把文本协议块解析成临时 `ToolIntent`，不能消费、删除、裁剪或改写原始正文。

Agent 运行时可以把解析出的临时工具意图交给工具执行链路，但不能把文本协议调用本身保存成类似原生工具调用的 invocation part。

Agent 运行时必须把原始助手正文完整保存。工具执行完成后，只把工具结果作为 part 保存。

后续模型请求如何投影历史上下文，是另一个独立设计问题。本文档不授权隐藏、删除、改写或转换历史正文中的文本协议调用；任何上下文投影改动都不能破坏“文本协议调用属于正文”的基本契约。

## 修改纪律

不要把文本协议工具调用擅自改成和原生工具调用一样的存储方式。任何会删除、改写、搬移 `message.content` 中 `TOOL_REQUEST` 文本的改动，都会改变会话正文契约，必须先询问用户，而不能当作实现细节自行决定。

不要把文本协议调用持久化为原生工具调用式的 invocation part。文本协议调用的持久化位置只有正文；part 只保存工具结果。
