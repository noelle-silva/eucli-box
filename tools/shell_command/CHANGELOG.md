# 更新记录

## 0.1.0 - 2026-07-26

- 建立本地非交互命令执行能力和独立的 Shell Provider 选择。
- 支持命令超时、输出截断、统一结果和编码诊断。
- 建立工具独立版本与 eucli-box 适用范围资料。
- 将工具本体与用户配置、运行资料分开保存。

## 未发布 - 2026-06-08

### 修复

- 修复命令输出捕获层对非 UTF-8 字节静默替换的问题。
- 修复长输出截断时可能把 UTF-8 多字节边界误判为乱码的问题。
- 改善 Windows 中文区域设置下，第三方外部程序通过 shell_command 输出中文时的乱码风险。

### 调整

- Provider 启动时会统一注入 UTF-8 运行环境提示，并覆盖冲突的旧环境值。
- 捕获 stdout、stderr 和合并输出时，会统一进行文本归一化。
- 输出中存在非 UTF-8 字节时，工具会保留可展示文本，同时返回明确的编码诊断信息。
- 工具结果内容在发生编码替换时，会在正文开头加入可见警告，避免 AI 或用户把替换后的内容当成完全可信的原始输出。
- 工具说明补充了 UTF-8 运行环境、编码诊断 metadata、异常编码处理建议。

### 新增

- 新增编码诊断 metadata，用于说明是否出现非 UTF-8 字节，以及 stdout、stderr、合并输出各自的替换情况。
- 新增真实入口集成测试：构建并启动 shell_command 可执行文件，验证外部程序收到 UTF-8 环境、正常中文原样返回、异常编码输出会被显式提示。
- 新增捕获层测试：覆盖正常 UTF-8 中文输出、截断边界、非 UTF-8 字节替换与提示。

### 验证

- 已运行 shell_command 真实入口详细实测，确认外部程序实际收到 UTF-8 运行环境。
- 已运行正常中文输出实测，确认中文文本原样返回且不会误报异常编码。
- 已运行异常编码输出实测，确认不可展示字节会被替换，并返回可见警告。
- 已运行 shell_command 全部测试。
- 已运行仓库全量 Go 测试。
- 已运行格式检查；仅出现 Windows 换行提示，无实质格式错误。
- 已运行 GitNexus 变更影响检测；本次 shell_command 范围为低风险，没有影响已识别执行流程。
- 已完成规范审查和破坏性审查；未发现确定问题。

### 说明

- 这次改动不是“所有旧式 Windows 原生程序的万能编码转换器”。
- 会遵守运行环境约定的外部程序，会更倾向于输出 UTF-8。
- 完全忽略运行环境的旧式程序仍可能输出本地编码字节；这类情况会由捕获层显式标记，而不是静默吞掉。
- 编码异常属于输出质量诊断，不等同于命令执行失败；判断命令是否成功仍应优先看工具状态和 exitCode。
